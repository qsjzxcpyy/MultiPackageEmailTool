# 订单审查自动化：任务计划

## 目标

盘点现有订单履约工作，识别可自动执行的步骤，提出插件/应用程序/接口自动化的选型，并设计一套在任何订单动作前可验证、可回放、可人工拦截的测试方案。第一阶段聚焦“订单是否有问题”的审查与邮件确认，不触发真实订单操作。

## 阶段

- [completed] 1. 盘点现有文档、表格和工作目录
- [completed] 2. 抽取订单审查的输入、规则、输出和人工决策点
- [completed] 3. 提出系统边界与实现方式（独立模块/统一应用）
- [completed] 4. 设计邮件确认 MVP 与安全闸门
- [completed] 5. 设计回放测试、影子运行和上线验收标准
- [completed] 6. 用户确认范围后编写设计规格与实施计划

## 约束

- 不以“100%准确”作为未经验证的宣传结论；必须通过规则闭环、人工审批、影子运行和可回滚机制逐步证明。
- 任何自动发邮件、冻结、取消、推单、改 SKU、改库存的动作默认需要人工确认，直到达到明确的上线门槛。
- 保护店铺、ERP、云仓和客户个人信息；不在代码或日志中保存明文密码、令牌和完整地址。

## 错误记录

| 错误 | 尝试 | 处理 |
|---|---:|---|
| 系统 `python.exe` 无法启动 | 1 | 改用工作区依赖目录中已加载的 Python 路径 |
| 系统 `rg.exe` 被拒绝访问 | 1 | 改用 PowerShell 只读枚举与搜索 |
| 当前目录不是 Git 仓库 | 1 | 保留现状；按工作目录文件进行分析，不执行 Git 写入 |
| PowerShell 内嵌 Python 引号解析失败 | 1 | 改用不含嵌套双引号的只读 Python 表格摘要命令 |
